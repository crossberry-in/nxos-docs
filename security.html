NoxOS Security — Threat Model & Hardening Log

Status: living document, updated every audit cycle. Nothing in here is aspirational: each entry points at real commits/tests.

1. Threat model (v0.3.1)

Adversary Capability Today Target (v0.4+)
Corrupted/malicious firmware Supplies DTB, device memory contents In scope (QEMU virt verified paths) Same, incl. real bootloaders
Malicious device DMA, config-space values, wedged registers In scope for the virtio paths in use + IOMMU/ACCESS_PLATFORM
Local app (EL0) Syscalls, IPC with hostile arguments Not yet possible (no EL0); syscall/IPC surface hardened ahead of it Primary adversary
Physical attacker Serial console, storage, package tampering Partially (log redaction) Signed packages, encrypted storage

Platform honesty: everything below is verified on QEMU virt (cortex-a53, GICv2, virtio-mmio v2) only. No phone/SoC security claim exists — see docs/HARDWARE_DEPENDENCIES.md.

2. Systemic invariants

  • no_std + #![deny(unsafe_op_in_unsafe_fn)]; unsafe blocks carry SAFETY comments.
  • Overflow checks on in ALL profiles (Cargo.toml [profile.release] overflow-checks = true): device-controlled arithmetic that would wrap in release aborts cleanly instead of corrupting state.
  • panic = abort (.cargo/config.toml): no unwinding through kernel code.
  • W^X at boot: image split into RO+X (vectors/text/rodata) and RW+XN (data/bss/stack) halves with 4 KiB granules; the VMM layer additionally rejects W+X and user+X mappings (validate_flags).
  • Capability-gated syscalls: unknown numbers rejected; every gated call checks the caller's capability set; unknown capability bits rejected at spawn; children inherit least privilege (DISPLAY only).

3. Red-team audit v0.3.1 (three independent reviewers)

Method: three parallel adversarial reviews (device-input parsing; memory/ arch/sync; syscall/IPC/UI bounds) over the full kernel, findings verified against exact source lines, then fixed and re-verified in QEMU.

3.1 Fixed (verified: make smoke PASS dev+release, graphics PASS, 120/120 host tests)

# Severity Where Issue Fix
1 HIGH sync.rs, boot.rs, interrupts/mod.rs, console.rs, syscall/mod.rs No IRQ-safe lock existed although the timer handler took TICKS/console locks that thread code also holds with IRQs enabled → guaranteed permanent deadlock on a tick landing inside a critical section New SpinLockIrq (DAIF save/mask/restore); all four IRQ-reachable statics (TICKS, REGISTRY, STATE, CONSOLE) converted; host tests added
2 HIGH boot.rs DTB acquisition Loader-supplied DTB pointer was volatile-read with only a magic check, before exception vectors were installed dtb_address_ok(): 4-byte alignment + inside platform RAM before any read; scan results re-validated; virt::RAM_SIZE used instead of hardcoded 512 MiB
3 MEDIUM fdt/mod.rs FDT bounds checks were relative to the 1 MiB probe slice, not the blob — bytes beyond the DTB could be parsed as reservations/structure Fdt::new narrows the view to the header's total_size
4 MEDIUM boot.rs probe window Fixed 1 MiB DTB slice could run past the end of RAM Window clamped to RAM end
5 MEDIUM boot.rs reservations Reservation parse failure silently disabled ALL firmware exclusions (unwrap_or(0)) Parse error is fatal (boot parks)
6 MEDIUM boot.rs/frame.rs Unchecked div_ceil(page)*page on device region starts — release wrapped to physical 0 Checked alignment; unalignable regions skipped
7 MEDIUM plan_usable Overlapping/duplicate DTB memory regions accepted → same frame handed to two consumers Sort + coalesce before gap emission
8 MEDIUM virtio/mod.rs Unbounded reset spin on a device-controlled status register Bounded (TRANSPORT_SPIN_BUDGET) → Timeout error; queue-ready read-back also bounded; queue size rounded to power of two
9 MEDIUM virtio/gpu.rs Device-reported resolution stored unclamped; check-then-use on DMA-visible pmode pmode copied to local once; validated (w,h ≠ 0) and clamped ≤ 8192; fb_len ≤ u32::MAX before MemEntry
10 MEDIUM boot.rs image map Whole kernel image mapped RW+X (one 2 MiB block) W^X split (see §2), verified by MMU-on smoke
11 MEDIUM page_table.rs unmap_range performed no TLB maintenance — a freed translation stayed live (future munmap escape primitive) tlbi vmalle1is + DSB/ISB flush after teardown (mmu::tlb_flush_all_el1)
12 MEDIUM syscall/mod.rs EXIT Task-id/pid namespaces conflated: a task could retire an unrelated process sharing its numeric id Explicit task→pid mapping recorded at spawn; EXIT resolves through it; unmapped task → ESRCH; tests updated + new test
13 MEDIUM syscall/mod.rs PUTCHAR No capability check: any caller could forge kernel log lines / monopolise the UART Gated behind new CONSOLE_WRITE capability; kernel context updated; tests added
14 MEDIUM scheduler/mod.rs block()/exit() left stale ring entries → blocked tasks kept being scheduled; freed slot replay panicked (expect) Ring remove() on block/exit; schedule() skips non-Ready entries; enqueue_ready pushes before marking Ready
15 MEDIUM ui/home.rs, ui/boot_screen.rs, graphics/surface.rs, ui/runtime.rs Device-reported dimensions used in unchecked u32 arithmetic → abort on edge-case scanouts Saturating layout math; zero-size rect guard; checked fb size math
16 MEDIUM (privacy) exception.rs Fault dumps printed full register file + FAR/ELR/SP to the always-on serial log Release builds log class/fault-status only; full dump behind debug_assertions

3.2 Deferred (tracked, with rationale)

Severity Area Item Why deferred
MEDIUM vectors.S RESTORE_ALL does not reload ELR/SPSR from the saved frame (handler edits to saved PC are dropped) No handler mutates the frame yet; must land before the first syscall PC-advance
MEDIUM vectors.S No double-fault stack: a corrupted kernel SP recurses in SAVE_ALL silently Needs per-CPU guard stack design; scheduled with SMP work
MEDIUM mmio.rs Accessors accept any address (no device-region registry) Closed in v0.6 (P2): device-region registry landed (RegionTable, register_region/_region accessors); the DeviceManager publishes every ingested DTB device range at discovery time. Early-boot UART/GIC keep the verified hardcoded constants by design
MEDIUM mmu.rs/VMM Single shared TTBR0 space, no kernel-VA reservation in VMM::map Must be fixed (TTBR1 split or reserved ranges) before EL0 ships; tracked as gate in roadmap P3
MEDIUM page_table.rs map_range has no rollback on mid-range failure (orphan mappings) Host-tested API rework planned with the VMM rework
LOW mmu.rs TCR.IPS defaults to 32-bit PA; regions beyond the programmed PA size not rejected QEMU virt RAM fits; clip in plan_usable when platforms with >4 GiB arrive
LOW arch/context.rs new_task_at entry/stack validation is debug-only Promote to runtime checks at first real spawn path
LOW ipc/mod.rs Channels cannot be destroyed (registry exhaustion DoS) Closed in v0.6 (P2): ChannelRegistry::close (owner-only, monotonic never-reused ids); host-tested
LOW syscall/mod.rs SPAWN name_ptr validated but unused; validate_ptr checks null/alignment only ABI to be finalised with real user-memory accessors
— Design Lower-EL faults/SVC currently fatal-park; caller identity is global, not per-CPU Redesign is part of the EL0 milestone gate
— Design No IOMMU / ACCESS_PLATFORM: any DMA-capable device can overwrite kernel memory virtio ACCESS_PLATFORM feature negotiation planned with DeviceManager

3.3 Secret hygiene findings
