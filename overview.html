NoxOS v0.6 — independent Rust kernel + device/communication foundation

Target profile: POCO M6 Pro 5G (sky family), Qualcomm SM4450, AArch64. Emulator bring-up platform: QEMU virt (verified contract).

What this project is

A compilable, bootable-with-graphics-in-emulation no_std Rust kernel:

v0.1 + v0.2 (preserved) - boot foundation: startup assembly, linker script, boot stack, BSS init, polled PL011 console, panic handler, DTB discovery/validation - AArch64 exception vectors with full register frames - memory: checked FDT regions, bump + bitmap frame allocators, 4-level page tables, W^X VMM, MMU enablement - GICv2 + ARM generic timer with an IRQ-driven tick - scheduler: TCBs, priority run queue, full-register context switch - syscall boundary (SVC), process table, capability-checked IPC - device service contracts (display/touch/storage/audio/net/USB/power — interfaces only, no hardware claims)

v0.3 (new — first graphical milestone) - virtio-mmio v2 transport driver (probe all 32 slots, modern layout, split virtqueue with bounded-spin submit/poll) - virtio-gpu display driver: the real command path GET_DISPLAY_INFO → RESOURCE_CREATE_2D → RESOURCE_ATTACH_BACKING → SET_SCANOUT → TRANSFER_TO_HOST_2D → RESOURCE_FLUSH - scanout resolution read from the device (720x1280 in the shipped profile — nothing hardcoded) - safe, bounds-checked software renderer + original NoxOS 5×7 font - design tokens (nox.theme seed) + two real scenes: a boot screen driven by 15 actual init stages and a home skeleton whose clock is refreshed once per second by the timer IRQ - physically contiguous framebuffer allocation (alloc_contiguous) - QMP screenshot capture of the real display output - automated boot tests for both the kernel (tests/qemu_smoke.sh) and the graphics path (tests/qemu_graphics.sh) - bug fix (v0.2 latent): context_switch rewritten as a #[naked] function; the old clobber_abi version could save a skewed SP (see docs/ANALYSIS.md)

v0.6 (new — P2 Device & Communication Foundation) - DeviceManager: heap-free device registry (monotonic ids, MMIO/IRQ resources), real-DTB discovery (45 compatible nodes ingested on QEMU virt), conservative class inference, compatible-string driver binding, checked lifecycle state machine with driver-failure recovery - capability model for devices: per-process open grants gated by DEVICE_OPEN/DEVICE_CONTROL; unauthorized access is structurally denied and exercised on every boot - MMIO device-region registry: every ingested device range is published to the checked accessors (closes a v0.3.1 deferred hardening item) - IPC v2: owner-only channel close (monotonic, never-reused ids), capability-gated shared-memory regions (ipc::shmem: create/grant/ attach/revoke/destroy), async event channels (ipc::events: per-subscriber bounded queues, all-or-nothing publish) - automated device gate: tests/qemu_devices.sh checks the whole device stage — discovery, binding, unauthorized-access denial and driver-failure recovery — on the real firmware DTB every run - release profile keeps overflow-checks = true; full gate (scripts/test.sh): fmt + clippy −D warnings + host tests + QEMU smoke + QEMU devices + QEMU graphics

What it looks like (real QEMU output)

All images are real QMP screendumps of the actual virtio-gpu scanout (720x1280), captured by scripts/capture_screenshots.py — not mockups. The v0.7 kernel runs a boot showcase tour (boot → lock → home → drawer → control center → terminal → settings → files → multitask → home) with smooth eased slide transitions (~25 fps, per-transition frame timing reported over serial).

Boot: 15 real init stages. Lock/home: uptime clock (no RTC driver yet — the only honest time source), aurora wallpaper, app tiles. Terminal: neofetch with real kernel values (version, uptime, scanout resolution, usable RAM, DTB device count). Weather card shows no temperature — no network stack yet; radios show N/A; folders show "No VFS yet". Scenes are rendered UI, not interactive apps: input driver and EL0 userspace are still pending (P3/P4), stated on-screen.

Prefer not to build? Grab the prebuilt package from the releases page: NoxOS-v0.3-emulator.zip (kernel ELF + run-noxos.sh / run-noxos.bat + docs + tests) or the full source tree as NoxOS-v0.3-source.zip.

What it is not

Not a phone image, not an Android replacement, not flashable. The phone boot contract remains UNVERIFIED — see docs/HARDWARE_DEPENDENCIES.md. Do not flash this project to a phone. QEMU graphics success proves nothing about the phone; see docs/KNOWN_LIMITS.md for the full honest-scope list.

Debian setup (NoxS)

sudo apt update
sudo apt install -y build-essential git curl pkg-config qemu-system-arm

Install Rust with the official rustup installer, then:

rustup toolchain install stable
rustup target add aarch64-unknown-none
rustup component add rustfmt clippy

Build & quality gates

cargo fmt --all -- --check
cargo clippy --workspace --target aarch64-unknown-none -- -D warnings
cargo test -p noxos-kernel --target x86_64-unknown-linux-gnu   # 116 tests
./scripts/test.sh            # all of the above + QEMU boot tests

Run it

make image                    # build the ELF
make qemu                     # headless boot, serial smoke check
make qemu-graphics            # headless boot with the display device
make screenshots              # capture boot/home screens via QMP
DISPLAY_BACKEND=gtk make gui  # real QEMU window (interactive session)

Expected serial output ends with [boot] ALL SMOKE CHECKS PASSED followed by the graphics chain [nox-gpu] … SCANOUT LIVE 720x1280, [nox-ui] BOOT SCREEN COMPLETE and [nox-ui] HOME SCREEN RENDERED, then periodic [tick] lines while the on-screen clock updates.

Real captured output: screenshots/ (boot + home screens), docs/logs/boot-graphics.log.

QEMU contract (emulator only)

-M virt -cpu cortex-a53 -m 512M -nic none \
-global virtio-mmio.force-legacy=off \
-device virtio-gpu-device,xres=720,yres=1280

force-legacy=off selects the modern (v2) virtio-mmio register layout the driver implements. The kernel still probes every transport slot at runtime and reads the resolution from the device.

NoxOS Preview APK (public releases)

android-app/ holds NoxOS Preview — a zero-dependency Android shell that replays this kernel's 15-stage boot sequence and home skeleton with the same nox.theme tokens (see android-app/README.md for the honest scope: it does not boot the kernel on-device). CI builds signed APKs on every app change and publishes pre-releases to the public download channel crossberry-in/NoxOS-App (.github/workflows/release-apk.yml). The app/kernel source stays closed in this repository.
