NoxOS architecture v0.2

NoxOS is an independent AArch64 operating-system research project. This document describes the architecture as implemented in v0.2 and the security invariants enforced by the code.

Kernel boundary

The privileged kernel (EL1) owns: - exception entry/return and interrupt dispatch (v0.2: implemented) - physical and virtual memory management (v0.2: frame allocator, page-table walker, VMM with W^X validation; MMU enabled at boot) - scheduler and process address spaces (v0.2: scheduler + kernel-task context switching; user address spaces pending) - system-call validation (v0.2: SVC dispatch with argument validation and capability checks; EL0 boundary pending) - capability checks and IPC primitives (v0.2: capability-gated channels)

User-space services should own display composition, audio policy, networking, storage policy and device management where the hardware access model permits.

Boot flow (QEMU virt, verified)

  1. boot/asm/entry.S — entered at EL1 (QEMU direct ELF boot); enables FP/SIMD access (CPACR_EL1.FPEN, required because the compiler emits NEON for wide copies), installs the 64 KiB boot stack, zeroes .bss, preserves x0 and calls rust_start.
  2. boot/src/main.rs — panic handler + transition into the kernel.
  3. kernel::boot::run — console init, privilege normalisation (ensure_el1, no-op when already at EL1), DTB discovery (x0 contract first, then a RAM scan for the FDT magic because QEMU's ELF path does not pass the pointer), FDT parse (memory regions + reservations), frame allocator, exception vectors, GICv2 + generic timer, identity page-table build, MMU enable, syscall state, scheduler bring-up, IRQ unmask.

See docs/BOOT.md for the full contract and docs/HARDWARE_DEPENDENCIES.md for every constant and its verification status.

Memory management

  • memory::frame — BumpFrameAllocator (boot phase, checked) and BitmapFrameAllocator (free-capable, caller-supplied bitmap).
  • memory::page_table — hardware-independent descriptor encoding and a walker over a TableProvider trait (identity-mapped provider in the kernel, arena provider in tests). Supports 4 KiB pages and 2 MiB / 1 GiB block descriptors; unmap collapses empty table chains.
  • memory::vmm — records mappings and enforces W^X and user-page privilege rules before any descriptor is written.
  • The boot identity map covers the kernel image (RW+X — per-section W^X split is a pending hardening task), the DTB, usable RAM (RW, XN), and the GIC/UART device windows (Device-nGnRE, XN).

Scheduling

scheduler::RunQueue — 32 fixed priority levels with a bitmap ready mask and fixed-capacity FIFO rings per level (no heap). tick() rotates the running task for round-robin fairness; block/wake/exit manage state. The v0.1 Scheduler trait and task types are preserved.

arch::context::CpuContext captures the complete integer register file (x0–x30 + sp, 256 bytes). A cooperative switch therefore restores every register, including caller-saved x0–x17, which is required because the switch happens at an arbitrary Rust statement where the compiler may keep live values in caller-saved registers. clobber_abi("C") plus a compiler_fence in the switch routine keep the compiler's view correct; the routine deliberately avoids options(noreturn) (see the module documentation for the failure mode this avoids).

Security invariants

  1. Validate all boot-provided pointers and lengths before parsing. (v0.2: FDT parser is fully bounds-checked; DTB magic/size validated.)
  2. Never map untrusted device memory as executable. (v0.2: device windows are Device-nGnRE + XN by construction.)
  3. Keep user pages non-privileged and enforce W^X where supported. (v0.2: VMM rejects write+execute and user+execute mappings; the kernel image is mapped RW+X pending per-section split.)
  4. Validate syscall arguments and IPC message lengths. (v0.2: pointer null/alignment checks, fixed-size messages, unknown syscall numbers rejected, capability checks on the caller.)
  5. Do not expose raw physical addresses to applications.
  6. Use capability checks for device/service access. (v0.2: PROCESS_SPAWN / IPC_SEND / IPC_CHANNEL_CREATE gates.)
  7. Keep a recoverable development environment; do not overwrite device partitions during early bring-up. (v0.2: no flashable image is produced; the boot target is the emulator.)

Device support

The initial device profile is POCO M6 Pro 5G / Xiaomi Sky family / Qualcomm SM4450. The profile is descriptive, not a verified boot configuration. No MMIO addresses, kernel load address, UART address, GIC base, clock tree, panel timings or touch-controller details are assumed for the phone. The QEMU virt platform constants (platform::qemu_virt) are the only hardware addresses in the tree and are verified for the emulator only.
