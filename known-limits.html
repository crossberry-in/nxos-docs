NoxOS v0.3 — Known Limits & Honest Scope

This file exists so that nobody (including future contributors) mistakes an emulator result for a hardware result, or a skeleton for a product.

What IS proven (QEMU virt, verified this milestone)

  • The kernel boots, validates the DTB, enables the MMU, services timer IRQs through the GIC, and runs the cooperative scheduler demo (tests/qemu_smoke.sh).
  • A virtio-mmio v2 transport driver probes all 32 transport slots and finds the virtio-gpu device (device ID 16, reported at slot 0xa003e00 on QEMU 10).
  • The virtio-gpu driver completes the real command path: GET_DISPLAY_INFO → RESOURCE_CREATE_2D → RESOURCE_ATTACH_BACKING → SET_SCANOUT → TRANSFER_TO_HOST_2D → RESOURCE_FLUSH.
  • The scanout resolution comes from the device (720x1280 is what QEMU reports; nothing is hardcoded).
  • The NoxOS software renderer draws the boot screen (with live init progress) and the home skeleton through that scanout — verified by QMP screendumps (screenshots/) and by the automated marker test (tests/qemu_graphics.sh).

What is NOT true yet — do not assume it

  1. This is not a phone OS image. The POCO M6 Pro 5G (SM4450) boot contract is still unverified. Nothing here flashes, boots, or claims to boot on the phone. QEMU success proves nothing about the phone.
  2. No 3D / GPU acceleration. virtio-gpu 2D scanout is a shared- memory blit path, not a GPU driver. There is no OpenGL/Vulkan claim anywhere.
  3. No input. There is no virtio-input (or any) driver; the home screen tiles are rendered UI, not interactive applications. The screen says so.
  4. No wall-clock time. The home clock shows uptime from the architectural counter (CNTFRQ/CNTPCT); there is no RTC driver.
  5. TCG cache-coherency assumption. QEMU TCG does not emulate CPU caches, so the queue/framebuffer RAM needs no cache maintenance under TCG only. KVM or real hardware bring-up must give the shared buffers DMA-coherent mappings or explicit cache ops before reusing drivers/virtio.
  6. Single core. -smp 1; secondaries park at entry. SMP is future work.
  7. Polling display queue. The control queue is driven by a bounded spin, not by the GIC interrupt. Transport IRQ acking is done but the IRQ is never awaited.
  8. Bump frame allocator never frees; alloc_contiguous strands leftover frames of skipped regions (accounted, documented). A free-list allocator is still on the roadmap.
  9. Home screen tiles are placeholders. They are honest pixels, not applications; no window manager, compositor, or app runtime exists yet.
  10. No Mozhi runtime, no Studio, no SDK in v0.3 — those phases are unstarted; see docs/MILESTONES.md for the honest status board.
