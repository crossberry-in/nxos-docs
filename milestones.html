Milestone 8 — v0.6 P2 Device & Communication Foundation ✅

Ten features in the master-spec P2 order, each with a Rust implementation, automated host tests and QEMU verification (tests/qemu_devices.sh boots the kernel and checks the device stage on the real firmware DTB):

# Feature Where Verified by
1 Device Registry (heap-free records, monotonic ids, MMIO/IRQ resources) kernel/src/devices/mod.rs 29 host tests
2 Device Discovery (real-DTB ingestion of compatible nodes) fdt::Fdt::device_nodes → DeviceRegistry::ingest_node QEMU: 45 nodes on QEMU virt
3 Device Capability Model (DEVICE_OPEN/DEVICE_CONTROL, per-device grants) DeviceRegistry::open/control/close host tests + QEMU "unauthorized open denied"
4 Driver Binding (compatible-string match tables) DeviceRegistry::register_driver/bind QEMU: 33/45 devices bound (PL011 + 32 virtio buses)
5 Device Lifecycle (state machine + driver-failure recovery) activate/suspend/resume/fail/remove host tests + QEMU recovery probe
6 IPC v2 (owner-only channel close, never-reused ids) ipc::ChannelRegistry::close host tests; closes SECURITY deferred DoS item
7 Capability-based permissions (graded bits at every entry point) security::CapabilitySet v0.6 bits host tests + QEMU probe
8 Shared Memory (SHM_CREATE/SHM_MAP, grant/revoke/destroy) ipc::shmem host tests; page mapping = P3 milestone (documented)
9 Async Event Channels (EVENT_BIND, all-or-nothing publish) ipc::events host tests; wait-queue wake-up = EL0 milestone (documented)
10 QEMU Device Tests tests/qemu_devices.sh + boot device stage ALL DEVICE CHECKS PASSED on the real DTB

Honest scope: the device stage is kernel-state bookkeeping — it proves the registry/discovery/binding/grant machinery against the real firmware-provided DTB but does not claim new hardware drivers. The virtio-gpu display keeps its verified v0.3 bring-up path.
