NoxOS v0.3 — Repository Analysis Report

Scope: full inspection of the existing tree before any v0.3 modification, as required by the development contract. The v0.2 foundation was treated as read-only reference material and preserved.

Tree inspected

  • boot/ — entry assembly (asm/entry.S), linker script (linker.ld, load address 0x40200000, vectors-first layout), boot image crate with the panic handler (src/main.rs), build script handing the linker script to rustc.
  • kernel/src/lib.rs — no_std kernel library; v0.1 primitives preserved and v0.2 modules: arch (CurrentEL/DAIF/EL2-drop helpers), boot (10-stage boot sequence), console (polled PL011 + kprint!), drivers (device service contracts), fdt (bounds-checked DTB reader), interrupts (GICv2 + generic timer), ipc, memory (regions, bump/bitmap frame allocators, 4-level page tables, W^X VMM), platform (QEMU virt constants + SM4450 profiles), process, scheduler (priority bitmap run queue), security (capability set), sync (spin lock), syscall (SVC boundary).
  • devices/xiaomi/sky/device.toml — phone profile, all entries UNVERIFIED (correctly so).
  • Makefile, tests/qemu_smoke.sh, docs set.

Findings at analysis time

  1. Working and verified (v0.2): boot → DTB scan → frame allocator → vectors → GICv2 → identity map + MMU → syscall install → scheduler demo → timer IRQs; 91 host unit tests; QEMU smoke markers.
  2. Latent defect found by v0.3 (fixed, see below): the cooperative context_switch used clobber_abi("C") inline assembly. LLVM may emit a prologue around such a block (it did: 80 bytes for d8–d15 + x30). The outgoing context's saved SP was captured after that push and the matching pop sat on the never-executed epilogue path, so every resumed task ran 80 bytes deeper into the stack than the compiled continuation expected. v0.2 never re-read caller stack state after the demo, so the bug stayed latent there; v0.3's graphics bring-up re-read the frame allocator afterwards and exposed it. Fix: the switch is now a #[naked] function (arch/aarch64/context.rs) — no prologue, exact SP contract. A bisect log and the disassembly evidence are in the v0.3 working notes; the fix is covered by the QEMU smoke test resuming the boot task and by alloc_contiguous allocations succeeding after the demo.
  3. Gaps relevant to graphics (all closed in v0.3): no virtio-mmio transport, no display driver, no software renderer, no font, no UI layer, no alloc_contiguous for device buffers, no MMU mapping for the virtio window (0x0a000000).
  4. Preserved untouched: every v0.1/v0.2 module listed above; the v0.2 smoke marker set ([boot] ALL SMOKE CHECKS PASSED) still passes byte-for-byte (tests/qemu_smoke.sh).

v0.3 additions (on top of the preserved foundation)

  • kernel/src/drivers/virtio/ — virtio-mmio v2 transport (probe, reset, features, split queue, bounded-spin submit/poll) + virtio-gpu device driver (display info, 2D resource, backing, scanout, transfer, flush).
  • kernel/src/graphics/ — original 5×7 NoxOS bitmap font, safe bounds-checked Surface renderer (host-tested), device-shared framebuffer handle (the only unsafe pixel path, documented).
  • kernel/src/ui/ — design tokens, boot screen scene (real init progress), home skeleton (IRQ-driven uptime clock), aarch64 runtime glue.
  • memory/frame.rs — alloc_contiguous for physically contiguous device buffers (+ host tests).
  • Boot sequence extended (stage 11) with an optional, fail-open graphics bring-up; the idle loop now refreshes the home clock once per second from the timer tick.

Verification artifacts: screenshots/ (QMP screendumps of the actual scanout), docs/logs/boot-graphics.log (serial markers), tests/qemu_graphics.sh (automated), docs/KNOWN_LIMITS.md (honest scope).
