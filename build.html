Building NoxOS v0.2 on NoxS Debian

1. Toolchain

sudo apt update
sudo apt install -y build-essential git curl pkg-config qemu-system-arm

Install Rust via the official rustup installer (download the script, inspect it, then run it):

curl -sSfO https://sh.rustup.rs      # or fetch from https://sh.rustup.rs
less rustup-init.sh                  # inspect before running
sh rustup-init.sh --profile minimal

Open a new shell, then:

rustup toolchain install stable
rustup target add aarch64-unknown-none
rustup component add rustfmt clippy
rustc --version    # v0.2 was developed and verified with 1.99.x

2. Build checks

cd noxos-v0.2
cargo check --workspace
cargo fmt --all -- --check
cargo clippy --workspace --target aarch64-unknown-none -- -D warnings

Note: .cargo/config.toml sets the default build target to aarch64-unknown-none with panic=abort; host tests pass the host target explicitly.

3. Host unit tests

cargo test -p noxos-kernel --target x86_64-unknown-linux-gnu

91 tests cover: FDT parsing (synthetic blobs), frame allocators, the page-table walker (map/translate/unmap/granules/overflow), the VMM (W^X), the scheduler (priorities, rotation, block/wake, capacity), IPC queues and capability-checked channels, the syscall dispatcher (validation, errno semantics, capability gates), capability sets, and the spin lock (multi-threaded contention).

4. Bootable image (QEMU)

make image      # = cargo build -p noxos-boot --features boot-image

The ELF lands at target/aarch64-unknown-none/debug/noxos (linked at 0x40200000, vector table first — asserted by boot/linker.ld).

5. Run in QEMU

make qemu       # 8-second run, serial log captured to /tmp/noxos-qemu.log

or manually:

qemu-system-aarch64 -M virt -cpu cortex-a53 -m 512M \
    -nic none -nographic \
    -kernel target/aarch64-unknown-none/debug/noxos

Success criteria (also automated by tests/qemu_smoke.sh): - [boot] DTB ok: ... - [boot] MMU enabled: true - [sched] resumed boot task after demo - [boot] ALL SMOKE CHECKS PASSED - periodic [tick] lines (IRQ-driven timer)

Exit QEMU with Ctrl-A X.

6. Troubleshooting

Symptom Likely cause
failed to find romfile "efi-virtio.rom" add -nic none (no NIC) or install the qemu data packages
boot stops after DTB discovered kernel linked below 2 MiB over RAM base — QEMU skipped the FDT install; keep BASE_ADDRESS = 0x40200000
Undefined Instruction at boot FP/SIMD trap — CPACR_EL1.FPEN not enabled (see boot/asm/entry.S)
no [tick] lines, unhandled INTID 1022 spam interrupt configured to Group 1 while the kernel runs in Secure state — keep the Group 0 bring-up in interrupts/gic.rs
