NoxOS Design System — v0.7 seed (nox.theme)

The NoxOS visual language is original: an aurora blue→violet wallpaper, card surfaces, colorful app tiles, a light "shell" variant (settings / files), and honest status colors. The concrete tokens live in kernel/src/ui/theme.rs; every scene must reference tokens, never raw colors.

v0.3 → v0.7 changes

  • Wallpaper: flat navy → aurora blue-violet gradient + two soft glows.
  • Scenes: boot + home skeleton → full showcase set (lock, home, drawer, control center, terminal, settings, files, multitask) with eased slide transitions (~25 fps, timing reported over serial).
  • Font: lowercase glyphs + # @ $ ~ added; ( / ) orientation fixed.
  • New primitives consumers: rounded cards, chips, switches, sliders, page dots, home indicator, 30+ geometric pictograms (ui/icons.rs).

Component seeds shipped in v0.3

  • BootScreen — moon mark, wordmark, progress bar (real init stages), status list (+ done / > active / . pending).
  • Progress bar — rounded track + fill, integer fraction mapping.
  • Status bar — brand left, live value right, hairline separator.
  • Uptime clock — large scale text over the wallpaper.
  • Dock tile — rounded rect surface with centred label (rendered placeholder until input exists).

The seed in action (real QEMU output)

Both screens are real QMP screendumps of the device scanout — every color and radius on them comes from the token table above.

Rules

  1. Scenes are pure functions over a Surface; no global state.
  2. Layout derives from the device-reported scanout size — no resolution is hardcoded anywhere.
  3. Text is uppercase Latin for v0.3 (the 5×7 set covers A–Z, 0–9 and basic punctuation); other scripts are a later typography phase.
  4. Every screen must state honestly what is not real yet (see the home footer and docs/KNOWN_LIMITS.md).
